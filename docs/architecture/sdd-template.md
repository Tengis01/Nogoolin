# SDD загвар - Nogoolin

**M2 · Тэнгис · 2026-09-21 · v0.2 · Бөглөх загвар**

SRS нь системээс шаардах үр дүнг, SDD нь түүнийг хэрэгжүүлэх аргыг тодорхойлно. Lecture 02-ын M2 заалтын дагуу энэ бүтэц бэлтгэв. Доорх асуултуудыг дараагийн ажлаар бөглөнө; бүрэн архитектурын баримт биш.

## 1. Зорилго ба хамрах хүрээ

*[Бөглөх: ямар SRS хувилбар, FR/NFR ID-г энэ дизайн хангах вэ? Хэн унших вэ?]*

Эхлэл: Nogoolin; [Scope Charter](../requirements/scope-charter.md), [таван шаардлага](../requirements/requirements.md). Уншигч нь хөгжүүлэгч Тэнгис, хичээлийн багш.

## 2. Системийн орчин ба бүрэлдэхүүн

*[Бөглөх: системийн хил, гаднын оролцогч, бүрэлдэхүүн бүрийн үүрэг ба холбоо. Context diagram нэм.]*

Эх материал: [Nogoolin public repository](https://github.com/Tengis01/Nogoolin), web/admin, API, өгөгдөл/auth, shared validation; [Phase 0 index](../phase-0/README.md). Эдгээрийг бэлэн архитектурын нотолгоо гэж үзэхгүй, холбогдох кодтой тулгана.

## 3. Архитектурын шийдвэр

*[Бөглөх: шийдвэр, хувилбарууд, сонгосон шалтгаан, сул тал, хангах requirement ID.]*

Карт: **Decision ID:** `[D-XX]`; **Requirement:** `[FR/NFR-XX]`; **Сонголт:** `[…]`; **Үндэслэл/эрсдэл:** `[…]`; **Source:** `[…]`.

Next.js, Fastify, Supabase зэрэг технологийн сонголтыг [шийдвэрийн эх](../../agent-context/DECISIONS.md)-ээс нягталж энд оруулна. “Хэрэглэгч юу хийж чадах вэ?” гэсэн шаардлагыг технологийн нэрээр орлуулахгүй.

## 4. Өгөгдөл ба хамгаалалт

*[Бөглөх: entity/холбоо, ownership, эрх, өгөгдлийн lifecycle; шаардлагын ID ба ER эх.]*

Эхлэх жишээ: NFR-01-ийн хувийн өгөгдөл тусгаарлах шаардлагад session identity, ownership filter, RLS/RBAC ямар үүрэгтэйг тайлбарлана.

## 5. Интерфэйс ба ажиллах урсгал

*[Бөглөх: интерфэйсийн contract холбоос, бүрэлдэхүүн хоорондын дараалал, хэвийн/алдааны урсгал.]*

FR-01-ийн асуулга илгээх урсгалаас эхэлнэ. API field/schema-г нэг эхэд хадгалж, энд холбоно; [OpenAPI](../phase-0/06-api-spec.yaml)-г кодтой тулгах шаардлагатай.

## 6. Чанарын шаардлагыг хангах арга

*[Бөглөх: NFR ID → дизайны арга → шалгах арга → эрсдэл.]*

Жишээ чиглэл: NFR-02-д fallback, NFR-03-д тестийн хаалт. Арга төлөвлөсөн эсэх, хэрэгжсэн эсэх, шалгасан эсэхийг ялгана.

## 7. Байршуулалт ба хамаарал

*[Бөглөх: local/test/production орчин, компонент байрших газар, build/deploy хамаарал, тохиргооны нэр.]* Нууц түлхүүрийн утга бичихгүй. [Deployment эх](../phase-0/09-deployment.md)-ийг ашиглана.
