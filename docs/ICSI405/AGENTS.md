# ICSI405 — Хичээлийн ажлын дүрэм

Энэ файл нь ICSI405 хичээлийн хавтас болон дэд хавтаснуудад ажиллах бүх шинэ chat/session-д мөрдөх хэрэглэгчийн тохиролцоо юм. Ажил эхлэхдээ энэ файлыг уншиж, тухайн семинарын одоогийн эхүүдийг шалгана. Хэрэглэгчийн дараагийн тодорхой заавар эдгээр ерөнхий дүрмээс давуу үйлчилнэ.

## Даалгаврын шаардлага ба эх материал

- Тухайн семинарын handout-ийг үндсэн шаардлага болгоно. Харгалзах lecture-ийг уншиж, ойлголт болон аргачлалыг нь ашиглана.
- Лекц ба семинар өөр ангилал хэрэглэвэл хооронд нь андуурахгүй. Жишээлбэл Seminar 1-ийн Getting Started / Tutorial / Reference / API нь Lecture 1-ийн User / Developer / Operations / Process ангиллаас өөр.
- Гаралтын тоо, бүтэц, үгийн хязгаарыг тухайн даалгавар болон хэрэглэгчийн заавраар тогтооно. Seminar 1-ийн дөрвөн PDF шаардлагыг бусад семинарт автоматаар бүү тулга.
- Шаардлагатай мэдээллийг эхлээд байгаа файл, кодоос олно. Хэрэглэгчийн өмнө өгсөн мэдээлэл, зөвшөөрөл, сонголтыг дахин асуухгүй.

## Хэл, найруулга

- Үндсэн бичвэрийг монгол кириллээр бичнэ. Код, API, file path, шаардлагатай техникийн нэр томьёог англиар үлдээж болно.
- Өөрийн төслөө тайлбарлаж буй оюутны энгийн, тодорхой найруулгыг хэрэглэнэ. Өөрийн дүгнэлтэд «би», «миний төсөл», «... гэж үзлээ» хэлбэр тохиромжтой.
- Хэт албан, хиймэл сүржин өгүүлбэр, давтагдсан тайлбар, хэрэггүй мета тэмдэглэл нэмэхгүй.
- Болор, Саруул зэрэг илүү зохиомол дүр, хуурамч ярилцлагын эшлэл, минутын roleplay хуваарь, зохиосон хэрэглэгчийн тестийн хариу бүү нэм.
- Бодитоор хийгээгүй ярилцлага, тест, хэмжилтийг хийсэн мэт бичихгүй. Байхгүй бол өөрийн ажиглалт, шинжилгээ, жишээ болгон найруулна.
- Persona эсвэл кейсийн байгууллага даалгаварт шаардлагатай бол хамгийн бага хэрэгтэй мэдээллээр өгч, жишээ гэдгийг товч тодруулна. Хэрэглэгчийн бодит намтар, ажилласан байгууллага болгон бүү танилцуул.
- Зохиомол эшлэл хассан зэрэг өөрчлөлтөөс даалгаврын шалгуур биелэхгүй үлдвэл «бүгд бүрэн биелсэн» гэж тайлагнахгүй. Дутуу шалгуурыг README-д товч тэмдэглэнэ.
- Бодит community асуудал, ном, documentation-ийг ашигласан бол шалгаж, эх сурвалжийг холбоостой нь хадгална. Өөр төслийн асуудлыг хэрэглэгчийн төсөлд болсон алдаа гэж бүү бич.

## LaTeX ба PDF-ийн хэв маяг

- Өөр формат хүсээгүй бол засварлах боломжтой LaTeX эх ба PDF гаргана. Одоо байгаа загварыг үргэлжлүүлж ашиглана.
- A4 хэмжээ, уншихад тохиромжтой үсгийн хэмжээ хэрэглэнэ. Одоогийн загвар нь XeLaTeX, Liberation Serif/Sans/Mono, үндсэн бичвэр 10.5 pt орчим.
- Догол мөрүүдийг хоёр талдаа тэгшилнэ (justify). Эхний мөрийг 1.25 см доголдуулна; гарчгийн дараах эхний догол мөрд мөн үйлчилнэ.
- Footer-т **зөвхөн хуудасны дугаар** байна. Огноо, «Сургалтын ажил» зэрэг бичвэр нэмэхгүй.
- Баримтыг боломжтой бол 1–2 хуудсанд багтаана. Эхлээд давхардсан тайлбар, шаардлага багатай хүснэгт, нэмэлт хэсгийг товчилно; үсгийг хэт жижигрүүлж багтаахгүй.
- Даалгаврын зайлшгүй агуулга, нотолгоо, үгийн тооны хязгаарыг хадгална. Жишээлбэл Seminar 1-ийн reflection яг 200 үгтэй байх ёстой.
- Хоосон шахуу хуудас, ганц гарчиг/эх сурвалж үлдсэн хуудас үүсгэхгүй. Хуудас таслалтыг шаардлагатай үед л хэрэглэнэ.

## Seminar 1-ийн одоогийн бүтэц ба команд

- `sem1/01_documentation_types.pdf` — 2 хуудас: гурван төслийн дөрвөн төрлийн харьцуулалт, өөрийн төслийн кейс.
- `sem1/02_audience_persona.pdf` — 1 хуудас: Тэнгисийн persona, гурван community асуудал, өөрийн дүгнэлт.
- `sem1/03_curse_of_knowledge.pdf` — 1 хуудас: README-ийн гурван Before/After засвар.
- `sem1/04_writer_in_the_middle.pdf` — 2 хуудас: 200 үгийн reflection, Corg.ly A–C кейс.
- `sem1/sem1_merged.pdf` — дээрх дарааллаар нэгтгэсэн 6 хуудас. Энэ тоо нь одоогийн төлөв; дараагийн даалгаварт тогтмол хязгаар биш.
- `sem1/latex/` — үндсэн эхүүд, `reflection_200_words.txt`, build болон Markdown экспортын хэрэгсэл.
- `sem1/wiki/` — Markdown хувилбарууд, `UE1_Corgly_Roleplay.md` (нэр нь хуучин боловч агуулга нь одоогийн кейс).

Шинэ `Nogoolin/docs/ICSI405` үндсэн хавтсаас:

```bash
# Агуулга зассан бол Markdown болон 200 үгийн эхийг нийцүүлэх
python3 sem1/latex/export_markdown.py

# Дөрвөн PDF-ийг хөрвүүлэх
bash sem1/latex/build.sh

# Одоогийн build.sh merged PDF үүсгэдэггүй тул тусад нь нэгтгэх
pdfunite sem1/01_documentation_types.pdf sem1/02_audience_persona.pdf sem1/03_curse_of_knowledge.pdf sem1/04_writer_in_the_middle.pdf sem1/sem1_merged.pdf
```

`export_markdown.py` нь reflection-ийн 200 үгийг шалгадаг. Хэрэглэгч цаашид үгийн шаардлага өөрчилбөл уг шалгалтыг мөн шинэчилнэ. `build.sh` зөвхөн PDF-үүдийг хөрвүүлдэг; файл ажиглаж автоматаар ажилладаг горим одоогоор байхгүй.
