## 0. Баримтын үүрэг ба хэрэглэх заавар

### 0.1 Үүрэг

Энэ баримт нь Ногоолин платформын **вэб public хэсгийн дизайны эх үнэн (source of truth)** юм. Дэлгэц бүрийн бүтэц, өнгө, хөдөлгөөн, харилцан үйлдэл, хүлээн авах шалгуурыг кодлоход хүрэлцэхүйц нарийвчлалтай тодорхойлно.

### 0.2 Claude Code хэрхэн хэрэглэх вэ

- Шаардлага бүр **WF-XX-NN** гэсэн ID-тай. `task.md` дээрх task-ууд эдгээр ID-г зааж subtask болгоно. Жишээ:
  ```markdown
  ## Task: Intro хэрэгжүүлэх
  - [ ] WF-INTRO-01 … WF-INTRO-09
  - [ ] WF-HERO-01 … WF-HERO-08
  - Acceptance: §8.1, §8.2
  ```
- Зөрчил гарвал давуу эрхийн дараалал: **энэ баримт → 02-requirements → prototype файлууд**. Prototype-д энэ spec-ээс зөрсөн 2 мэдэгдэж буй алдаа бий (§7.2) — spec-ийн дагуу засаж хэрэгжүүлнэ, prototype-ийг хуулбарлахгүй.
- Бүх хэмжигдэхүүн (hex, px, vh, рад, сек) энд бичигдсэнээрээ хэрэгжинэ. "Ойролцоогоор" гэсэн утга байхгүй.
- §6-д заасан **хойшлуулсан шийдвэрүүдийг** таамаглаж хэрэгжүүлэхийг хориглоно — тэдгээр газарт тохиргоо/тогтмолоор ил гаргаж, шийдвэр гарахад нэг мөрөөр солигдохоор бич.

**Палитрын дүрмүүд (WF-DS-03):**

1. Гүргэм шар зөвхөн **текст, hairline, badge, halo** дээр — том fill талбайд хэзээ ч хэрэглэхгүй.
2. `--act` (#0BB555) бол цорын ганц үйлдлийн өнгө. Шар товч хийхгүй (анхааруулгын семантиктай давхцана).
3. Улаан өнгө v4-д **байхгүй**. Ёслолын гүн улаан accent-ийг Phase 3-т эргэж харна (§6).

## 2. Хөдөлгөөний зарчим v2 (түгжсэн) (WF-MO-01…03)

Бүх одоогийн болон ирээдүйн animation шийдвэрийн шүүлтүүр — гурван дүрэм:

- **WF-MO-01. Бурхан хөдөлгөөнгүй.** 3D модел (одоо placeholder орб, Phase 3-т Ногоон Дарь Эхийн GLB) ямар ч эргэлт, хэлбэлзэл, bobbing хийхгүй. Үл хамаарах цор ганц зүйл: Detail хуудасны 360° viewer — тэнд **хэрэглэгч өөрөө** чирч эргүүлнэ (auto-rotate байхгүй).
- **WF-MO-02. Орчин "амьсгална".** Амьд үлдэх зөвшөөрөгдсөн зүйлс зөвхөн: тоосонцрын хөвөлт, гэрлийн intensity-гийн зөөлөн хэлбэлзэл, halo-гийн opacity-гийн зөөлөн хэлбэлзэл (§3.1.4-ийн томьёогоор). Өөр юу ч биш.
- **WF-MO-03. Камер зөвхөн зорилготой үед хөдөлнө.** Хоёр л тохиолдол: (а) интроны нэг удаагийн ирэх нум, (б) "Эхлэх" дарахад хийгдэх morph. Idle sway, loop, autoplay огт байхгүй. Бүх камерын хөдөлгөөн smootherstep easing-тэй: `e(t) = t³(t(6t−15)+10)`.

#### 3.1.3 Камерын ирэх нум (WF-INTRO-02)

Ганц зөөлөн нум — баруун дээрээс урд төв рүү. Эргэлт (orbit/spiral) **хориотой**.

| Параметр | Эхлэл | Төгсгөл |
|---|---|---|
| Azimuth (рад) | 0.85 (~49°, баруун-дээд) | 0 (урд төв) |
| Radius | 16 | 6.2 |
| Өндөр (y) | 7.5 | 2.2 |
| lookAt | (0, 1.4, 0) тогтмол | мөн |
| Үргэлжлэх | 5.0 сек, smootherstep | — |

```js
const az = 0.85 * (1 - e);
camera.position.set(r*Math.sin(az), y, r*Math.cos(az));
camera.lookAt(0, 1.4, 0);
```

Нум дуусмагц камер **бүрэн зогсоно** (WF-MO-03).

#### 3.2.3 Бурханы баруун байрлал — асимметр проекц (WF-HERO-02) ⚠ ЧУХАЛ

**Хориглоно:** Камерыг хажуу тийш зөөх (lateral translate). Шалтгаан: камер x-тэнхлэгээр шилжихэд бурхан руу харах шугам `atan(shift/r) ≈ 18–21°` өнцгөөр хазайж, бурхан + ард нь байрлах halo хооронд параллакс үүсэн "бурхан эргэж байгаа" мэт харагдана. Энэ алдаа v4 prototype дээр илэрсэн (§7.2).

**Зөв шийдэл:** Камер бурханы тэнхлэг дээрээ үлдэнэ (x=0, lookAt(0,1.4,0) хэвээр). Framing-ийн шилжилтийг `PerspectiveCamera.setViewOffset()`-оор хийнэ — проекцын цонх шилждэг тул бурхан **яг эгц урдаасаа** харагдсан хэвээр frame-ийн баруун талд байрлана. Өнцгийн өөрчлөлт, параллакс огт үүсэхгүй.

```js
// e = morph easing (0→1); w,h = hero-гийн одоогийн px хэмжээ
const OFF = window.innerWidth <= 700 ? 0.10 : 0.18; // frame өргөний хувь
camera.setViewOffset(w, h, -OFF * w * e, 0, w, h);
```

- offsetX **сөрөг** → бурхан frame-ийн баруун тийш шилжинэ.
- Morph дууссаны дараа утга тогтмол хадгалагдана (`clearViewOffset` дуудахгүй); window resize болгонд шинэ w,h-аар дахин тавина.
- Skip/reduced-motion/давтан зочны шууд-home замд e=1 утгаар шууд тавигдана.
