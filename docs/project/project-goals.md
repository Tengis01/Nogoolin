## 2. Төслийн гол зорилго

> **2027-01-29 гэхэд бодит дэлгүүрийн каталогийг Монгол хэлтэй, C дизайнтай web сайтаар public domain дээр нээж, зочин хүссэн бараагаа олоод алдаагүй асуулга илгээж, дэлгүүр түүнд 1 ажлын өдөрт хариулах урсгалыг ажиллуулна. Энэ ажлыг баримтжуулсан, шаардлагаас тест хүртэл холбогдсон чанартай хийнэ.**

## 3. SMART дэд зорилгууд

Зорилго бүр гурван хэсэгтэй:
- **outcome:** хэрэглэгчид гарах үр дүн;
- **launch шалгуур:** гаралтын тоо;
- **хэмжүүр:** хэмжих арга.

Хэмжээгүй зүйлийг хэмжсэн гэж бичихгүй. Хэмжилт хийгдэх хүртэл төлөв нь «зорилт — хэмжигдээгүй».

### G1 — Каталог launch

- **Outcome:** Зочин бодит дэлгүүрийн бараагаа онлайнаар олж, үнэ, зураг, хэрэглэх зааврыг нь дэлгүүрт очилгүйгээр харна.

| | |
|---|---|
| **S** | Бодит дэлгүүрийн бүтээгдэхүүнийг MN хэлтэй responsive web каталогт нийтэлнэ. |
| **M** | Launch шалгуур: ≥ 30 нийтлэгдсэн бүтээгдэхүүн. Тус бүр ≥ 3 бодит фото, тайлбар, хэрэглэх заавар, үнэтэй. Public domain дээр HTTPS-ээр нээгдсэн. Outcome-ийн хэмжүүр: usability task «X бараа олох»-ын completion rate ≥ 80%, median хугацаа ≤ 60 s (`docs/quality/usability-protocol.md`, planned). |
| **A** | Каталог болон admin CRUD хийгдсэн (PH3). Үлдсэн ажил нь админ засах хуудас болон контент оруулах. Бодит фото нь owner-оос хамаарна; зураг авалтын стандарт D-09-өөр тогтсон (D-03 хаагдсан). |
| **R** | Vision-ий гол цоорхой бол «онлайн каталог байхгүй» ([01-vision §2.2](../phase-0/01-vision.md#22-the-gap)). |
| **T** | 2027-01-29 (санал). Бүтээгдэхүүний контент 2027-01-15 гэхэд бүрэн орсон байна. |

### G2 — Inquiry-ийн үнэ цэн

- **Outcome:** Сонирхсон зочин бүртгүүлэлгүй асуулга илгээж, хүлээн авсан гэсэн баталгаа авна. Дэлгүүр асуулга бүрийг алдалгүй харж хариулна.

| | |
|---|---|
| **S** | Бүтээгдэхүүний хуудаснаас inquiry илгээх. Admin inbox-оос харах, төлөв солих. |
| **M** | Usability task «асуулга илгээх»: completion ≥ 90%, median ≤ 2 мин, баталгаажуулалтын алдаанаас гарч чадаагүй тохиолдол 0. Launch-аас хойш 4 долоо хоногийн турш inquiry-ийн тоо болон 1 ажлын өдөрт хариулсан хувийг (зорилт ≥ 90%) inbox-ийн төлөвөөс хэмжинэ. |
| **A** | API болон web урсгал хийгдсэн (PH4). Хариулах ажлыг дэлгүүрийн хүн хийнэ. |
| **R** | Vision-ий «inquiry customer» persona ([§3.2](../phase-0/01-vision.md#32-secondary-user--the-inquiry-customer-phase-4)). Захиалга/төлбөр идэвхжээгүй үед борлуулалтын цорын ганц суваг. |
| **T** | Урсгал staging дээр PH5-ийн төгсгөлд. Хэмжилт launch + 4 долоо хоног (≈ 2027-02-26). |

### G3 — Premium туршлага ба гүйцэтгэл

- **Outcome:** Зочин сайтыг хурдан, итгэл төрүүлэхүйц, соёлын хувьд хүндэтгэлтэй гэж мэдэрнэ. Интро нь каталогт хүрэхэд саад болохгүй.

| | |
|---|---|
| **S** | C дизайныг (D-08) production web-д нэвтрүүлж, бодит Green Tara GLB-ийг интрод ашиглана. |
| **M** | GLB ≤ 5 MB. Production build, Lighthouse mobile preset (lab) дээр нүүр, жагсаалт, дэлгэрэнгүй хуудас: Performance ≥ 90, Accessibility ≥ 90, SEO ≥ 90, LCP < 2.5 s, CLS ≤ 0.1. Хэмжих нөхцөл нь 1 warm-up + 5 sample, median. Босгыг PH2-ийн baseline хэмжилтийн дараа эцэслэнэ. Интро: skip ≤ 1 s-д харагдана, reduced-motion үед хөдөлгөөнгүй. |
| **A** | Prototype C нь урсгалыг баталсан. GLB болон фото owner-оос ирэх ёстой, энэ нь гол эрсдэл. |
| **R** | Vision-ий «Trust / Premium Experience» үнэт зүйл. |
| **T** | 2027-01-15 (санал, PH5-ийн төгсгөл). |

### G4 — Чанар ба traceability

- **Outcome:** Launch-ийн дараа хэрэглэгч гол урсгал дээр critical алдаатай тулгарахгүй. Өөрчлөлт бүр аль шаардлагад хамаарахыг хөгжүүлэгч мэднэ.

| | |
|---|---|
| **S** | Must шаардлага бүрийг тесттэй холбож, CI gate-ээр хамгаална. |
| **M** | [Traceability](../requirements/traceability-v2.md)-д Must шаардлагын 100% нь verification-тэй (тест эсвэл inspection). CI-д шаардлагатай integration тестүүд skip-гүй ажиллана (SRS v1.0 NFR-03 gap хаагдана). Launch-ийн өмнө нээлттэй **S1** алдаа 0. Алдааны түвшин S1–S4-ийг `docs/quality/test-plan.md` (QA-01, planned) баримтад тодорхойлно. |
| **A** | Тестийн суурь бий (Sem6 unit, integration). QA хичээлийн агуулга ирэхэд стратегийг тааруулна. |
| **R** | Portfolio зорилго: «production-quality engineering» ([01-vision §11](../phase-0/01-vision.md#11-project-constraints)). |
| **T** | 2027-01-22 (PH6-ийн төгсгөл). |

### G5 — Баримт ба portfolio

- **Outcome:** Шинэ хөгжүүлэгч эсвэл reviewer төслийн аль ч баримтыг нэг бүртгэлээс олж, бодит кодтой нийцсэн мэдээлэл авна.

| | |
|---|---|
| **S** | ICSI438-ийн ажил бүрийг төслийн албан ёсны баримт болгож, [Document Register](../README.md)-д бүртгэнэ. Docs site нийтэлнэ. |
| **M** | Register-ийн MVP баримтууд «approved» төлөвтэй. Дотоод холбоос эвдрэл 0 (lychee эсвэл script). ICSI438-ийн seminar гаралт бүр нэг бүртгэлтэй баримт руу заана. |
| **A** | Хичээлийн ажил аль хэдийн хийгдсэн. Ажил нь нэгтгэх болон шинэчлэх. |
| **R** | Portfolio зорилго. Хичээлийн W10 (docs CI) болон W14–W15 (final pitch). |
| **T** | Семестрийн W15 (≈ 2026-12-14 долоо хоног; хуанли баталгаажаагүй). |

### G6 — Mobile (дараагийн release)

- **Outcome:** Mobile app хэрэглэгч каталог үзэж, асуулга илгээнэ.

| | |
|---|---|
| **S** | Expo app-д inquiry болон C дизайныг нэмж, internal testing-д гаргана. |
| **M** | Android болон iOS internal testing build ажиллана. Mobile дээрх inquiry урсгал web-тэй ижил шаардлагыг (FR-INQ) хангана. |
| **A** | Web launch-ийн дараа. Apple developer эрх ($99/жил) шаардлагатай. |
| **R** | Хэрэглэгчид гол төлөв mobile-аар орно ([01-vision §9](../phase-0/01-vision.md#9-constraints-and-assumptions)). Гэхдээ responsive web эхний хэрэгцээг хангана. |
| **T** | **Тогтоогоогүй.** Launch-аас хойш owner тогтооно. |
